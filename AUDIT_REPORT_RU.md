# CIRCLES CONTROL 3.7.2 — отчёт об изменениях и проверках

## Исходная база

В основу репозитория положены runtime-файлы комплекта CIRCLES CONTROL Smart Cleaner 3.7.1: `combined_multi_account.py`, `broadcast_core.py`, `smart_cleaner.py`, `telegram_manager_web.py`, `telegram_manager_panel.html`, а также исходные unit-тесты. В исходном runtime веб-панель использует `TelegramManagerRuntime` из `telegram_manager_web.py`; это важно для совместимости модулей и не должно смешиваться с отдельной ранней реализацией `SmartManagerServer`.

## Исправления 3.7.2

### 1. Сохранение ручного контроля над рассылкой

В `run_service()` раньше вызывался `bc.resume()` независимо от `broadcast_autostart`. При сохранённом `broadcast_state.json` кампания могла возобновиться после рестарта даже при выключенном автозапуске.

Теперь `bc.resume()` вызывается только при `broadcast_autostart=true`. При выключенном флаге активное и ещё не истёкшее состояние очереди сохраняется, но автоматическая отправка не стартует. Явная команда `--broadcast` и ручной запуск из панели по-прежнему могут запустить/продолжить кампанию.

### 2. Больше никаких скрытых изменений политики аккаунта

Удалены два блока автоматической миграции, которые при запуске могли менять `broadcast_allowlist_only`, `broadcast_allowlist` и `broadcast_auto_subscribe` в конфиге профиля. Запуск CIRCLES CONTROL и дополнительных профилей больше не должен самовольно расширять список получателей или включать автоподписку. Изменение этих параметров остаётся явным действием владельца.

### 3. Безопасный порядок закрытия SQLite

В `Broadcaster.close()` фоновая задача рассылки теперь сначала ожидается (с ограниченным временем ожидания и отменой при превышении таймаута), и только после её завершения закрываются `Store` и durable action queue. Это устраняет гонку, при которой `send_wave()` мог вызвать `self.skip.report()` после закрытия SQLite-соединения.

### 4. Чистый репозиторий и воспроизводимый запуск

Добавлены `requirements.txt`, `requirements-dev.txt`, `setup.sh`, `start.sh`, systemd-установщик, `.gitignore`, CI workflow и инструкции на русском/английском. Секреты, сессии, конфиги, базы, очередь рассылки и runtime-данные в Git не помещаются.

## Проверки, выполненные в среде сборки

- `compileall` для runtime и тестовых Python-файлов — успешно.
- Regression tests для условий автозапуска, порядка SQLite shutdown, неизменности политики профиля и использования уже зарегистрированных клиентов — 5 passed.
- Проверка JavaScript UI отдельно запускалась; результат будет указан по фактическому запуску перед публикацией.

## Ограничения

Среда сборки не имеет сетевого доступа к PyPI и здесь не установлен Telethon. Поэтому полный набор тестов, требующий Telethon, нельзя честно объявить выполненным локально. GitHub Actions устанавливает зависимости из `requirements-dev.txt` и выполняет полный тестовый набор. Реальный Telegram login, live API, systemd и поведение на пользовательских сессиях требуют проверки на VPS.
